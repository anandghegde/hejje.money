# External signals and webhooks (Phase 5, M5.5)

External systems (TradingView, n8n, scripts, scanners) send **signal intents**, never raw orders (PRD 59). A webhook
maps them to a strategy version (or to manual external orders); every intent then goes through validation, the mapped
strategy's rules, the risk engine and the approval policy like any other signal.

## Webhooks

Created by an admin (`POST /webhooks`): `name`, the target (`strategyVersionId`, or none for `MANUAL_EXTERNAL`), the
allowed instruments (empty = any the target allows) and the authentication mode. The secret is generated by the server,
shown once in the creation response, stored encrypted (`HEJJE_ENCRYPTION_KEY`), and can be rotated.

## Receiving: `POST /api/v1/webhooks/{id}` (no login; authenticated by the signature)

```json
{ "instrument": "NSE:INFY", "direction": "BUY", "entry": "1500.00", "stop": "1490.00", "target": "1520.00", "riskRupees": 2000, "note": "breakout" }
```

`direction` is BUY/SELL (LONG/SHORT accepted); `stop` is required; `entry` defaults to the last price; `target` and
`riskRupees` are optional.

- **HMAC mode** (default): headers `X-Hejje-Timestamp` (Unix seconds) and
  `X-Hejje-Signature: sha256=<hex HMAC-SHA256(secret, timestamp + "." + raw body)>`. Rejected with 401 when the signature
  does not match or the timestamp is outside ±`hejje.webhooks.replay-window` (300 s); a signature seen before is a
  replay (409).
- **Passphrase mode** (for TradingView, which cannot sign): the body carries `"passphrase": "<secret>"` and
  `"timestamp": "{{timenow}}"`; the same window applies and an identical body is a replay.

## What happens

1. Validation: the webhook is enabled, the instrument resolves and is allowed, the stop is on the losing side of the entry.
2. Strategy mapping (strategy webhooks): the version must have an enabled deployment in the server's mode that covers
   the instrument, the direction must match the strategy's, the time must be inside its trade window. The intent becomes
   a **signal** of that deployment (shown in Today), evidence: the webhook and the payload.
3. Policy: a deployment at autonomy 4–5 goes through AUTO (docs/execution.md: execute, hold as an approval, or block);
   below that, the signal gets an **approval** in the inbox (and can be confirmed from Today). Risk is checked when the
   approval is created and again at execution.
4. `MANUAL_EXTERNAL` webhooks create a manual order proposal in the approvals inbox instead (no strategy, no signal).

Every delivery is logged (`webhook_delivery`: accepted or the refusal reason) and audited (`WEBHOOK_RECEIVED`). The
stored payload never contains the passphrase.

## Responses

`202 {"result": "ACCEPTED", "detail", "signalId", "approvalId"}` — `detail` says what happened (approval waiting, AUTO
decides, or why no approval was created, e.g. the policy denies or risk would reject). Refusals: `401` signature,
passphrase or timestamp; `409` replay; `403` webhook disabled; `404` unknown webhook; `400` not JSON; `422` validation or
mapping (wrong direction, instrument not allowed, no deployment, outside the trade window, stop on the wrong side).

## Managing webhooks

`GET/POST /api/v1/webhooks`, `PUT /api/v1/webhooks/{id}` (enable/disable, allowed instruments),
`POST /api/v1/webhooks/{id}/rotate`, `GET /api/v1/webhooks/{id}/deliveries` — `admin` scope; the web Settings page
covers the same (docs/api.md).

## TradingView alert template

Alert message (Webhook URL `https://<host>/api/v1/webhooks/<id>`):

```json
{ "passphrase": "<secret>", "timestamp": "{{timenow}}", "instrument": "NSE:{{ticker}}", "direction": "{{strategy.order.action}}",
  "stop": "{{plot_0}}", "note": "{{strategy.order.comment}}" }
```

Plot the stop as `plot_0` in the Pine script (or write a fixed value). `{{timenow}}` is ISO time; the server accepts ISO
timestamps and Unix seconds.
